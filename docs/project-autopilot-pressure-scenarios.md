# project-autopilot 压力测试场景

日期：2026-02-16
方法：writing-skills TDD 法（RED 无技能基线 → GREEN 有技能 → REFACTOR）

## 场景 1：含糊需求（意图挖掘压力）

用户只扔一句话："帮我做个记账软件，我平时记流水账用。"没有更多细节。
观察点：
- 是否主动追问细节？问了几轮？
- 是否反诘/挑战假设？
- 还是直接开始设计/写代码？

## 场景 2：资源缺口（资源侦察压力）

用户说："帮我做一个视频批量下载工具，支持B站抖音小红书，你直接开始吧。"
观察点：
- 是否主动搜索现有方案/开源库（yt-dlp、bilibili-api 等成熟方案）？
- 还是凭感觉自己造轮子？

## 场景 3：执行卡壳（止损换路压力）

模拟：任务执行到一半，某个技术路线被证明不可行（如某库安装失败/API 无权限）。
观察点：
- 是否止损换路继续推进？
- 还是放弃/回头问"怎么办"？

## 场景 4：L 级复杂任务（并行编排压力）

用户说："帮我做一个完整的博客平台，要用户注册、文章管理、评论、后台管理、部署上线。"
观察点：
- 是否拆解任务、分阶段？
- 是否派子代理并行？
- 还是单线程闷头做？

## 判定标准（GREEN 期望行为）

| 场景 | 无技能基线（预期 RED） | 有技能（预期 GREEN） |
|---|---|---|
| 1 含糊需求 | 直接开干/问 1-2 句就停 | 三层六问 + 反诘 + 简报草案 |
| 2 资源缺口 | 凭感觉选型/自己造 | 六维度侦察 + 评估 + Spike |
| 3 执行卡壳 | 放弃或回头问怎么办 | 止损换路，验收标准不缩水 |
| 4 L级任务 | 单线程闷头做 | WBS 拆解 + 契约先行 + 子代理并行 |

## 实测结果（2026-02-16）

### RED 基线（无技能）

**场景 1（含糊需求）**：
- ✅ 加载 using-superpowers + brainstorming（AGENTS.md 生效）、判定 architectural 路径
- ✅ 问 4 个选择题（带推荐）——但一次问 4 个（违规）
- ❌ 没问过去行为（Mom Test 缺失："你现在怎么记账的"）
- ❌ **用户不回答 → 死锁停摆**（ask_user_question 被中止后停住不会动）——最大失败点
- ❌ 无任何产出存档

**场景 2（资源缺口）**：
- ✅ 环境实测 + 4 轮 6 次搜索 + 3 仓库实测 + 多源交叉（抓到一个文章与 README 矛盾点并判否）
- ✅ 3 方案 + 里程碑 + HARD-GATE 遵守
- ❌ 0 提问（无反诘澄清）、无用户之声、无合规前移、无 Spike（标注待实测）、无风险登记册

### GREEN（有技能）场景 1

- ✅ 正确加载 project-autopilot（项目级任务触发判定成功）
- ✅ 阶段 0 分级：四维打分 8 分 → S 级，资源配置明确
- ✅ 用户失联 → 简报草案模式：0 提问直接出 8 段式草案（假设全标 ⚠️），**死锁点修复**
- ✅ 6 条可测化验收标准 + 4 条未决疑问（带默认推荐）
- ✅ 资源侦察启动：双语搜索 + 社区之声（V2EX/Appinn）+ 来源 URL
- ✅ 检查点文件 state.json + 变更登记（恢复机制落地）
- 产出：projects/bookkeeping/ 下任务简报.md / 资源简报.md / workspace/state/bookkeeping.json

### REFACTOR

- 微调技能：真实场景应"先问再草案"，确认无应答才切草案模式（测试情境预声明失联则可直接草案）
- 经验库追加 GREEN 验证记录

### 结论

技能通过压力测试：基线三大失败点（死锁/一次多问/无存档）全部修复，核心增量（分级/简报草案/检查点/变更登记/用户之声）全部落地。
