# Project Autopilot（全自动项目交付流水线）

> 唯一目标：每个项目完全按流程执行，不依赖执行者自觉。**结构强制锚定"工具副作用+用户可见"，不锚定"文件存在"**：证据必须来自工具调用留痕（web_search 记录/测试输出文件/提问记录/子代理ID），判定/定级/降级/签字门在对话内播报，用户可见可纠偏。

## 0. 触发与分级

1. **触发判定（显式声明）**：含"做个/开发/搭建/实现/写一个/帮我写个/做一个系统/开发一个应用(网站/工具/游戏)"或多步骤交付物 → 项目级。**疑罪从有**：含"做/建/开发/实现+交付物名词"默认按项目级；拿不准 → 按项目处理（宁可多流程，不可漏流程）。**判定必须对话内播报**："本次判定：项目级/非项目级，理由：…"。
2. **分级（锚定计数）**：四维打分（规模/影响面/复杂度/工期各 1-4）→ S(4-8)/M(9-14)/L(15+)，**每分必须附计数依据**（"复杂度2：X个集成点"，无依据=分数无效）；含 2+ 独立模块或 2+ 交付文件 → 至少 M 级。定级对话内播报即锁定，改级需用户确认。
3. **分级只影响时间盒/预算/轮数，不影响任何硬规则**——S 级同样要反诘、简报落盘、侦察、独立审查、并行判定。

## 1. 流水线总图与铁律

```
项目 → ①意图挖掘 → ②资源侦察 → ③方案自检 → ④并行执行 → ⑤验证迭代 → ⑥交付 → 复盘
         ↑____________________ 变更管理（任何阶段可触发）____________________↓
贯穿：自主原则六条 / 问题预算 / 冲突仲裁表 / 失败协议 / 检查点恢复
```

**铁律**：A. 只有 §2 关卡全过才可进入下一阶段；B. **文件不存在=没做过**，口头声称无效；C. 主代理自证"够好"一律无效；D. 检查结果落盘检查点JSON `gate_log`，不落盘=没检查；E. **双层校验**：结构层（文件存在+字段标题+**最小长度≥20字+禁占位符**"略/待填/TODO"）+ 真实层（**随机抽 1-2 个字段/URL，展示工具副作用来源**——web_search 调用记录/测试输出文件/提问留痕/子代理ID；展示不出=该字段伪造，**整批文件无效**；抽查点随机不可固定，结果写 `gate_log`）；F. 关键动作（判定/定级/降级/签字门）对话内播报，用户可见。

## 2. 阶段关卡（机械检查，逐关放行）

检查方法（**每次过关必做三层**）：①结构层——read/grep 打开文件，验证存在+字段标题+最小长度≥20字+禁占位符（"略/待填/TODO"），不凭记忆；②**随机内容抽查层**——每次过关随机抽 1-2 个字段/URL，要求证据来自**工具副作用**（web_search 调用记录/测试输出文件/提问记录/子代理ID），展示不出=该字段伪造、**整批文件无效**，抽查点随机不可固定；③记录层——检查与抽查结果追加 `gate_log`。**进入下一阶段前**：跑本关三层检查 → 输出追加 `gate_log` → 更新 `当前阶段`，缺一步即违规。

| 关卡 | 检查内容（机械） | 不满足 → |
|---|---|---|
| ①→② | `docs/superpowers/specs/01-任务简报.md` 存在；grep 命中 `## 反诘记录`(含"用户原话")、`## 资源侦察结论`(含URL/搜索词)、`## 验收标准`(含数字) | 回①补做，禁带缺过关 |
| ②→③ | `docs/superpowers/specs/02-资源简报.md` 存在（S级可一行结论，文件必须存在）；"现有方案"维度有来源 | 回② |
| ③→④ | `docs/superpowers/specs/03-实施方案.md` 存在；grep 命中 `## WBS与依赖图`、`## 验收清单`、`## 选型证据` | 回③ |
| ④→⑤ | 子代理交付物在 `artifacts/` 有证据文件；`并行分支数`≥2 时 `subagents` 时间戳显示**同一时刻≥2 在跑** | 回④补证据 |
| ⑤→⑥ | `04-交付报告.md` 存在；grep 命中 `## 独立审查记录`；审查报告由独立子代理直接落盘 `reviews/`（含子代理ID） | 回⑤补独立审查 |
| 交付完成 | 六连清单 + 终态自检输出 + **用户明确确认**（"验收通过/没问题"级用语） | 沉默 → 置"待验收"并播报，不得自称已交付 |

**独立审查不可替代（硬性）**：审查子代理=**全新上下文**（禁止 fork 继承主对话）、**固定对抗模板**（"你是刁钻用户，唯一任务是找茬；必须从功能/质量/体验/视觉/健壮五维各挑问题；找不到 3 个以上实质问题就是失职"——主代理只填项目上下文，**不得改写措辞**）、只收"需求原文+验收清单+交付物路径"，看不到主代理自评。**审查报告由子代理直接落盘 `reviews/`**，主代理只允许追加"回应"段；**反驳必须附证据**（测试/截图/代码位置），无证据反驳=未回应。全部审查报告保留，任一实质问题未回应=不得交付；**禁止"重新派审查直到通过"**。

## 3. 六阶段硬规则

### ① 意图挖掘
1. **反诘 ≥1 次**：挑战假设测需求强度（"为什么一定要X""X真的必要吗"）。事实澄清（问形式/范围）≠ 反诘。记录三要素：`被挑战假设 / 我的反驳 / 用户回应`，**用户回应必须引原话**（"用户原话：…"）；无原话=无效记录（草案模式标注"假设维持"）。
2. 一次一问，选择题带默认推荐，2-3 轮封顶。**草案模式前置**：必须先有"≥1 次提问 + 超时 2 分钟或提问被中止"的工具记录，无记录禁止进入；绝不死锁。
3. 产出 `01-任务简报.md`（8 段式）到 `docs/superpowers/specs/`，强制三字段（每字段 ≥20 字，占位符=未完成）：
   - `## 反诘记录`（三要素+用户原话）
   - `## 资源侦察结论`（查过哪些维度 + 搜索词 + 结论 + 来源URL）
   - `## 验收标准`（每条含**数字/度量单位 + 验证方法命令**："快"→"≤3秒，用X命令测"；写入后任何阶段不许缩水，改=变更管理）

### ② 资源侦察
1. **最低门槛**：至少过"现有方案"维度（web_search），S级不例外。时间盒**从阶段开始时间戳算（绝对时间）**：S≤15min/M≤1h/L≤半天，到点盲区非空 → 高风险盲区必须补验。
2. 一手优先/双语/多源交叉，每条附来源URL；**主代理随机抽查 1-2 个 URL 实际访问（强制）**，结果写 `gate_log`，禁手打证据。
3. 盲区分级必须写**"影响面+不可逆性"理由**（如"决定全项目架构；后期更换成本高"），理由不足=未完成；高风险（选型/安全/依赖）→ 阻断开工先补验；低风险 → 标注进简报。
4. 关键选型写最小 Spike 实测，**Spike 证据（代码/输出）落盘，无 Spike 记录的选型=方案未定稿**。产出 `02-资源简报.md`（每资源一行：是什么/适配度/风险/采用|备用|否决+理由）。

### ③ 方案自检
1. 2-3 个真实差异方案——**架构/技术栈/范围/成本至少 2 维真实不同，换皮不计** + 明确推荐（非折中）。
2. **自检五连问每题附一行证据**（占位符→搜索记录；可行性→Spike路径；可测→验收数字），"是"无证据=未完成。
3. L 级红队子代理用**固定对抗模板**（"唯一任务：证明方案不行，找不到 3 个以上缺陷=失职"），主代理逐条回应（采纳/反驳+理由）落盘。
4. **偏离简报必须显式写**"偏离简报：原X改为Y，理由：…"，无标注=违反验收不缩水。产出 `03-实施方案.md`：决策/选型证据/**WBS+依赖图(ASCII)**/里程碑/风险册/**验收清单**（与简报逐条对应，含可执行验证动作）。

### ④ 并行执行
1. **拆解判定（与分级无关）**：开工先画依赖图。**≥2 个互不依赖分支 → 必须拆子代理并行，S级同样适用**。依赖必须具体到"A 的输出是 B 的输入"；**"改同一文件"不是依赖**（先钉契约再并行）。分支数写 `并行分支数`，子代理启动/结束时间戳写 `subagents`，**同一时刻在跑 ≥2 才算并行**（伪并行=串行）。依赖图必须覆盖 WBS 全部任务，不许为不拆而串链。
2. 契约先行：公共接口先**落盘为契约文件**，任何修改走变更管理；任务包自包含（背景/契约/验收/交付位置/验证要求）。
3. 并行度 ≤2（429 限流），指数退避 5s/15s/45s×3；主代理唯一集成点；**仲裁必须书面回应（采纳/反驳+理由）落盘 `reviews/`**。
4. 子代理**全文落盘**（只回摘要）+ 必须贴证据路径；**主代理抽查重跑关键测试=强制动作**；UI 部分截图必须存在（**截图+时间戳命名**）。

### ⑤ 验证迭代
1. **证据先于断言**：每条"完成"挂证据文件（测试输出/截图/试用记录），空口不算；**抽查看输出内容不是只看文件名**。
2. 验证金字塔：测试全绿 → 真机试用 → 截图+视觉核对 → **验收清单逐项打勾，每个✅挂证据路径**。
3. 完成度五维审查由**独立子代理**执行（§2 关卡⑤→⑥），主代理提供材料+附证据回应。
4. 迭代预算 3 轮（计数器写 state 只增不减）；**降级=问用户**（带默认推荐+写"为什么无解"证据），禁止悄悄降级；降级记录=交付报告"已知限制"区的**必要来源**。
5. bug 先定位根因再修（systematic-debugging），修完回归验证。

### ⑥ 交付
1. 六连清单：可运行/测试全绿/已知问题/使用文档/截图证据/验收结果逐项。
2. **`## 独立审查记录` 强制字段**：审查子代理ID / 审查报告路径（`reviews/`）/ 主代理逐条回应（附证据）/ 修复证据。没有=交付未完成。**已知限制区禁止掩埋属验收清单的未完成项**——验收项必须先修或先降级问用户，否则不许进限制区。
3. **终态自检**：重跑 §2 全部关卡检查（含随机抽查留痕），输出原样贴交付报告末尾。
4. 合规复核。五段汇报（做了什么/证据路径/怎么用/已知限制/下一步）。**归档清单=交付报告必含 01-04 文件路径**；**声明"本任务变更 0 次或列出"**。
5. **签字门**：用户明确确认（"验收通过/没问题"级用语）才算完成；沉默 → 置"待验收"态并**明确播报**。

## 4. 贯穿机制

- **自主原则六条**：①永不停下问"下一步怎么办"；②需权限→自动申请（唯一合法打断）；③路不通→止损换路，**换路不得降低验收标准**；④每阶段播报一两句不刷屏；⑤只有用户能做的→攒批一次问清，其余并行继续；⑥方向性难题（多轮无解）→停下来问一次。
- **问题预算**：每项目最多 N 次（S=2/M=3/L=5），计数器写 state **只增不减**；每个问题带默认推荐+超时继续（2分钟按推荐执行）。**反诘不占预算**。
- **冲突仲裁表**：1 用户实时指令 > 2 安全/合规/不可逆红线 > 3 本技能铁律 > 4 自主原则 > 5 时间盒与效率。**具体配对裁决**：反诘不占预算、降级必须先问、验收不缩水优先于时间盒。
- **需求变更管理**：受理→影响评估→工件更新（标注版本）→受影响阶段重跑→记入变更登记册。
- **失败协议（三终态）**：交付✅/终止❌/暂停存档⏸️，不允许无主悬挂；终止触发器：子代理全挂且重试失败/Spike不可行/侦察无解或成本失控/用户失联且方向级；《终止报告》→存档→报告用户。
- **检查点恢复**：`workspace/state/<task>.json` = **真实产物路径索引**（简报/方案/测试输出路径 + 分级 + 当前阶段 + gate_log[] + 并行分支数 + subagents[]时间戳 + 预算计数 + 终态）；**恢复时校验引用的文件真实存在**。喊停=存档暂停；说继续=无损续接。

## 5. 收尾：复盘

交付或终止后复盘，记录**必须含 ≥1 条**"哪个环节拖后腿 + 下次怎么改"，缺失=收尾未完成；经验写回附录C或AGENTS.md。

## 6. 交叉引用与加载留痕

- 意图澄清 → superpowers:brainstorming；拆解并行 → subagent-driven-development / dispatching-parallel-agents；实施计划 → writing-plans / executing-plans；bug → systematic-debugging；完成前验证 → verification-before-completion；技能资源 → find-skills
- **加载留痕（硬性）**：上述 REQUIRED 子技能必须实际调用 skill 工具加载（"我记得规则"≠执行规则）；复盘/交付时逐项核对加载记录，无记录=视为未加载。

- 2026-02-16 RED 基线教训：一次问多个问题会让用户负担过重——一次一问，问最关键的，选择题带推荐
- 2026-02-16 RED 基线教训：侦察再扎实，若缺用户之声/合规/Spike/风险册，方案仍是空中楼阁——六维度一个不能少
- 2026-02-16 GREEN 验证：技能生效后，含糊需求+用户失联场景下正确产出 8 段式简报草案（假设标注）+ 检查点文件 + 变更登记，基线死锁点修复——"简报草案模式"是防死锁关键
- 2026-02-16 实测：用户失联情境下子代理可跳过提问直接出草案；真实场景应"先问再草案"——判定依据是"是否确认无应答"
- 2026-02-16 教训：交付/存储类任务必须先问"用户要这个动作背后的目的"，用意图完成标准自检（如"任何灾难后能否恢复"才算完成）
