# project-autopilot 设计文档（红队加固版）

日期：2026-02-16
状态：已批准（用户最终批准，含三路红队裁决）

## 目标

开发一个名为 `project-autopilot` 的 agent 技能（SKILL.md），让 AI 接到项目任务后全自动跑完：意图澄清 → 资源侦察 → 方案自检 → 并行执行 → 验证迭代 → 交付。核心诉求：除权限/账号等必要操作外，用户无需主动操作或提醒；AI 主动克服一切困难。

## 触发方式

- frontmatter description：项目级/多步骤/要交付物的任务自动触发；单步问答不触发
- AGENTS.md 加触发指引（双保险）

## 六阶段流水线（红队加固版）

### 前置：项目分级（四维打分）

- 打分时机：意图挖掘后立即打分定级
- 四维：交付物规模（文件数/代码量）、影响面（用户数/系统数）、复杂度（技术难度/集成数）、预计工期
- 权重与映射写死；总分 4-8=S / 9-14=M / 15+=L
- **定级写入简报，中途不许改级**（改级需用户确认）——防"自评降级躲红队"

### ① 意图挖掘

- 心法：不问"想要什么"，问"解决什么"；问过去行为，不问未来假设（Mom Test）
- 三层六问：目标（解决什么问题/现状/痛点）→ 场景（谁用/什么场景/失败案例/边界）→ 约束（时间/预算/平台/维护者/验收标准可测化）
- 技法：反诘质询（始终尖锐，对内容不对人）/ 具象化测试（描述成品的一天）/ 形容词→验收指标
- 纪律：一次一问、给选择题带默认推荐；2-3 轮封顶
- **用户失联 → 简报草案模式**：按最合理假设生成草案并标注假设，侦察阶段照常推进，用户回来确认
- 产出：8 段式《任务简报》存档（背景/目标/用户/场景/边界/约束/验收标准/未决疑问），验收标准可测化自查

### ② 资源侦察

- 六维度双语信源：
  ① 现有方案：web_search + Google/Bing + GitHub + HN + 知乎/V2EX/少数派
  ② 开源库：GitHub API（星/活跃/许可）+ npm/PyPI 注册表 + awesome + Spike 实测
  ③ 技能：npx skills find + GitHub 技能仓库
  ④ 文档API：官方文档一手优先 + StackOverflow
  ⑤ 设计资产：Unsplash/Pexels/Fonts/Iconify + Figma
  ⑥ 用户之声：B站（免登录+客户端CDP）/ 小红书（用户已登录浏览器）/ 抖音（可选）；用用户语言搜索
- 纪律：一手优先 / 双语搜索 / 多源交叉 / 资源附来源URL可验证（防幻觉引用）
- 时间盒分级：S≤15min / M≤1h / L≤半天；到点收网
- **盲区分级**：高风险盲区阻断开工，只允许低风险盲区带病进入
- **合规前移**：许可证商用条款、API ToS 在选型时当场查
- 社区情报只当假设，需多平台交叉 + 与用户确认
- 关键选型自动 Spike 实测
- 登录策略：用户提前登录浏览器；掉线攒批提醒一次
- 产出：《资源简报》（决策区 采用|备用|否决 / Spike区 / 盲区）

### ③ 方案自检

- 2-3 个真实差异方案（稳妥/激进/极简）+ 明确推荐（非折中）
- 选型挂 Spike 证据；偏离简报必须显式标注理由
- 自检五连问：占位符 / 一致性 / 可行性 / 验收可测 / 范围
- L级派子代理红队挑刺，逐条回应（采纳/反驳）后才定稿
- 产出：WBS（工作分解）+ 依赖图（执行交接件）+ 风险登记册（风险→触发信号→预案→定期复查）+《实施方案》存档
- 分歧处理：只问花钱💸和不可逆⚠️，其余全自动

### ④ 并行执行

- 依赖图先行：无依赖并行 / 有依赖分阶段 + 阶段关卡
- 契约先行：公共接口钉死，谁也不许私自改
- 任务包自包含：背景/契约/验收/交付位置/验证要求
- **并发上限 2** + 错峰启动 + 429 指数退避（5s/15s/45s×3）+ 子代理只回摘要、全文落文件
- 沟通：共享工作区（artifacts/ + reviews/ 目录约定）+ 互相评审为主；"直接互发消息"当前运行时不可行（send_message 只能发给 direct child）→ 主代理转发；主代理唯一集成点+仲裁权
- 验证不信任：贴证据+主代理抽查+UI 截图
- 操作细节：项目根写 `.npmrc` 固定 cache 到工作区；Spike 跑服务用后台 job + 健康检查 + 输出重定向避管道 EPERM；GitHub API 未认证 60 req/h 配额

### ⑤ 验证迭代

- 宪法：证据先于断言——每条结论挂证据，空口不算
- 验证金字塔：测试全绿 → 用户视角真机试用 → 截图视觉核对 → 验收清单打勾
- 完成度五维审查：功能/质量/体验/视觉/健壮，逐项打勾
- 审查主体分离：主代理操作、独立子代理扮演刁钻用户挑刺（连点/缩放/非法输入/断网/点边缘），主代理逐条回应
- 刁钻用户操作协议：网页应用串行排期独立 tab；Electron 走 CDP；原生 Win32 回退 CLI/API 冒烟+静态审查
- 迭代轮数预算（3 轮），超预算走降级通道
- 降级=问你：多轮无解必须问你（带默认推荐），不许自动悄悄降级
- 确定性脚本校验（命令硬证据）+ 原始产物留档（测试输出/截图原件不许删）
- bug 纪律：先定位根因再修，修完回归
- 退出条件：清单全勾；钢琴块反面案例对照清单（点击无效/不居中/bug/完成度）

### ⑥ 交付

- 六连清单：可运行 / 测试全绿 / 已知问题清单（如实列）/ 使用文档 / 截图证据 / 验收结果
- 合规复核（许可证/API条款/隐私）
- 五段正文：做了什么 / 证据 / 怎么用 / 已知限制 / 下一步
- 对话汇报 + 存档；**交付报告 = 验收申请（签字门）**：你确认后才算交付完成；不回复则置"待验收"态（有终态）
- 归档：简报+方案+交付报告同处，全程可追溯

### 收尾：复盘机制

- 每个项目交付或终止后复盘：哪个环节拖后腿/踩了什么新坑/什么环节失效
- 成功失败都复盘，经验写回技能经验库（流水线自我进化）

## 贯穿机制

### 自主原则六条

1. 永不停下问"下一步怎么办"——自己决策、自己推进
2. 需要权限 → 自动发起权限申请（唯一合法"打断"）
3. 一条路不通 → 止损，重新侦察换路，绝不硬磨；**换路不得降低验收标准**
4. 进度播报：每阶段一两句，不刷屏
5. 只有用户能做的（账号/付费/人工审批）→ 攒批一次性问清，其余并行继续
6. 方向性难题（多轮迭代无解）→ 停下来问你一次

### 问题预算

- 每项目最多问 N 次（S=2 / M=3 / L=5），问完即止
- 每个问题必带默认推荐（你不答就按推荐走）+ 超时继续（等 2 分钟不回复按推荐执行）

### 冲突仲裁优先级表

1. 用户实时指令（最高）
2. 安全/合规/不可逆红线（删数据/花钱/对外发消息/隐私）
3. 技能铁律（证据先于断言/降级需确认/验收标准不缩水/定级不改）
4. 自主原则（默认全自动，受问题预算约束）
5. 时间盒与效率规则（最末，可被上面任何一级覆盖）

### 需求变更管理

变更受理 → 影响评估 → 工件更新（标注版本）→ 受影响阶段重跑 → 记入变更登记册

### 失败协议（三终态）

- 终态：交付 ✅ / 终止 ❌ / 暂停存档 ⏸️，不允许无主悬挂
- 终止触发器：子代理全挂且重试N次仍失败 / Spike证明方案不可行 / 侦察证明无解或成本失控 / 用户失联且问题属方向级
- 终止收尾：《终止报告》→ 存档 → 报告用户（失联则直接归档）

### 检查点恢复

- 简报/方案/进度记录全部落盘（workspace/state/<task>.json）
- 用户喊停 = 存档暂停；说继续就无损恢复（优先 send_message 续接而非重跑）

### 操作层细节（红队C实测）

- npm 缓存：项目根 `.npmrc` 写 `cache=C:\Users\lxx10\Desktop\deepseek\.npm-cache`；npx skills 固定 `npm_config_cache=...`
- 沙箱：写 `~/.dsh/skills` 需授权弹窗（已实测可授权）；npm 默认缓存不可写
- 子代理 vision：env 无 DEEPEYE_API_KEY，需显式传参约定
- 工具链：node 24.18 / python 3.12.5 / git 2.54 齐全；gh CLI 未装（GitHub API 未认证 60 req/h）
- 429 限流：并发上限 2、错峰、指数退避、摘要落文件

### 反面案例对照清单（钢琴块）

点击无效→真机试用连点测试 / 不居中→截图视觉核对 / bug多→系统化边界测试 / 完成度不够→五维审查清单
