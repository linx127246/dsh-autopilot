# 项目工作流程（实战定型版）

> 来源：五子棋小游戏任务实战（2026-08-17）。本文档描述"接到项目型需求后如何推进"的完整流程：
> 每阶段做什么、产出什么、怎么算过关、时间盒多少。以五子棋为实例走查，流程本身可复用。

---

## 0. 总览：六阶段流水线

```
接任务 → ①判定分级 → ②意图挖掘 → ③资源侦察 → ④方案自检 → ⑤并行执行 → ⑥验证迭代 → ⑦交付
                              ↑_________________ 变更管理（任何阶段可触发）_________________↓
```

铁律：A. 关卡全过才进下一阶段；B. 文件不存在=没做过；C. 主代理自证"够好"无效（要独立审查）；D. 检查结果落盘检查点，不落盘=没检查；E. 关键动作（判定/定级/降级/签字）对话内播报。

---

## 1. 接任务：判定 + 分级

**判定**（对话内播报"本次判定：项目级/非项目级"）：
- 含交付物名词（做个X / 开发X / 写一个X / 做一个系统）→ 项目级，走全流程
- 单步问答/闲聊/一次性小事 → 不触发，正常处理
- 拿不准 → 按项目处理（疑罪从有）

**分级**（四维打分，每分必须附计数依据）：
| 维度 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|
| 规模 | 单文件 | 少量文件 | 多模块 | 系统级 |
| 影响面 | 仅本机 | 单用户 | 多用户 | 外部服务 |
| 复杂度 | 无集成 | 1-2 集成点 | 多集成点 | 分布式 |
| 工期 | 当天 | 1-3 天 | 1 周 | 1 月+ |

S(4-8) / M(9-14) / L(15+)。**分级只影响时间盒与预算，不影响任何硬规则**。
（五子棋实例：1+1+1+1=4 → S 级；2 个独立分支 → 仍要并行执行）

---

## 2. 阶段① 意图挖掘：澄清需求

- **反诘 ≥1 次**：挑战一个隐含假设（"为什么一定要X？X真的必要吗？"），记录三要素：被挑战假设 / 我的反驳 / 用户回应（**必须引原话**）
- **提问规则**：一次一问、选择题带默认推荐、2-3 轮封顶；事实澄清 ≠ 反诘
- **验收标准**：每条必须含**数字/度量单位 + 验证命令**（"快"→"≤3秒，用X命令测"）；写入后任何阶段不许缩水，改 = 走变更管理

产出：`docs/superpowers/specs/01-任务简报.md`（需求/反诘记录/资源侦察结论/验收标准/风险/交付物）
过关检查：文件存在 + grep 命中 `## 反诘记录`（含用户原话）、`## 资源侦察结论`（含URL/搜索词）、`## 验收标准`（含数字）

（五子棋实例：反诘"AI 是否必要"→ 用户选"人机对战（简单 AI）"；两轮提问定下模式与功能范围；验收 8 条全部可测化）

---

## 3. 阶段② 资源侦察：不重复造轮子

- **最低门槛**：web_search 过"现有方案"维度，附来源 URL，多源交叉
- **强制抽查**：随机抽 1-2 个 URL 实际访问，结果写检查日志（访问失败也记录在案）
- **Spike 实测**：关键选型写最小验证脚本（代码+运行输出落盘），无 Spike 证据的选型 = 方案未定稿
- **时间盒**（绝对时间）：S≤15min / M≤1h / L≤半天

产出：`docs/superpowers/specs/02-资源简报.md`（每资源一行：是什么/适配度/风险/采用|备用|否决+理由）

（五子棋实例：搜到评估函数方案 → GitHub 抽查被网络拒连（记录在案）、备用站点访问成功 → AI 算法 Spike 实测 7/7 用例通过、中盘 1ms，同时抓出"空盘无候选点"边界 bug）

---

## 4. 阶段③ 方案自检：决策留痕

- **2-3 个真实差异方案**（架构/技术栈/范围/成本至少 2 维不同，换皮不算）+ 明确推荐（非折中）
- **自检五连问**每题附证据：需求理解（用户原话）/ 可行性（Spike 路径）/ 可测性（验收数字）/ 风险可控（风险册）/ 工作量（分级依据）
- **偏离简报必须显式标注**："原X改为Y，理由…"

产出：`docs/superpowers/specs/03-实施方案.md`（决策/选型证据/**WBS与依赖图**/里程碑/风险册/**验收清单**）
过关检查：grep 命中 `## WBS与依赖图`、`## 验收清单`、`## 选型证据`

（五子棋实例：评估函数 vs Alpha-Beta vs 纯随机，附 Spike 证据；依赖图确认 core/UI 两分支只依赖契约文件）

---

## 5. 阶段④ 并行执行：契约先行

- **拆解判定**：≥2 个互不依赖分支 → **必须并行子代理**（同一时刻 ≥2 在跑才算并行，时间戳留痕）；"改同一文件"不是依赖
- **契约先行**：公共接口先落盘契约文件，两分支只认契约，改契约走变更管理
- **任务包自包含**：子代理提示词含背景/契约/验收/交付位置/验证要求；不得再派生子代理
- **子代理全文落盘**：报告+证据写文件，只回摘要；UI 分支必须附截图证据
- **主代理唯一集成点**：合并、重跑关键测试（强制抽查）、修契约偏离

（五子棋实例：契约文件钉死 8 个 API → core 分支（逻辑+AI+42 单测）∥ UI 分支（界面+自测 mock）同时开工；集成时发现 core 的 undo 语义偏离契约，主代理裁决修正并回归测试）

---

## 6. 阶段⑤ 验证迭代：证据先于断言

- **验证金字塔**：单测全绿 → 真机/浏览器实测 → 截图 + 视觉核对 → **验收清单逐项打勾，每条挂证据路径**
- **多通道验证**：不要单一通道空转——DOM 查询/测试输出/截图视觉交叉印证
- **bug 流程**：先定位根因再修（不要上来就改），修完回归验证
- **迭代预算 ≤3 轮**；降级（缩水验收）必须先问用户，写"为什么无解"证据
- 沙箱等环境限制：如实记录等价替代方式（如 node --test 子进程被拦 → 进程内模式）

（五子棋实例：42 单测独立重跑、性能脚本、浏览器整局实测（落子→AI→悔棋→胜利弹层→再来一局）、AI 崩溃注入实测、双视口截图 + 视觉模型复核，8 条验收逐项挂证据）

---

## 7. 阶段⑥ 交付：六连清单 + 签字门

1. **六连清单**：可运行 / 测试全绿 / 已知问题 / 使用文档 / 截图证据 / 验收结果
2. **独立审查**：全新上下文子代理 + 固定对抗模板（唯一任务找茬，五维：功能/质量/体验/视觉/健壮，找不到 3 个实质问题=失职），报告由审查子代理**直接落盘** `reviews/`；主代理逐条回应（附证据），反驳必须带证据
3. **终态自检**：重跑全部阶段关卡检查，输出原样贴交付报告
4. **五段汇报**：做了什么 / 证据路径 / 怎么用 / 已知限制 / 下一步
5. **签字门**：用户明确确认（"验收通过/没问题"）才算完成；沉默 → 置"待验收"播报

产出：`docs/superpowers/specs/04-交付报告.md`（含独立审查记录、变更登记、终态自检）

（五子棋实例：独立审查被用户按指令跳过（如实声明不伪造）；审查员终止前留下 1 条实质发现"AI 崩溃会卡死"，修复 + 注入异常实测通过后交付）

---

## 8. 贯穿机制

| 机制 | 规则 |
|---|---|
| 变更管理 | 需求变更：受理 → 影响评估 → 工件更新（标注版本）→ 受影响阶段重跑 → 记入变更登记册 |
| 问题预算 | S=2 / M=3 / L=5 次提问；每个问题带默认推荐 + 超时按推荐执行；反诘不占预算 |
| 冲突仲裁 | 用户实时指令 > 安全/合规红线 > 流程铁律 > 自主原则 > 时间盒 |
| 失败协议 | 三终态：交付✅ / 终止❌ / 暂停存档⏸️，不允许无主悬挂 |
| 检查点 | state 文件 = 真实产物路径索引（阶段/gate_log/并行时间戳/预算计数），可无损续接 |

## 9. 精简模式（本次实战教训）

本次 S 级任务被流程仪式拖慢（用户两次反馈"太慢了"）。**教训：流程的"量"按规模裁剪，"质"必须保留。**

| 场景 | 全流程 | 精简模式（推荐小项目） |
|---|---|---|
| 判定分级 | 四维打分+播报 | 一句话判定，省略打分 |
| 意图挖掘 | 反诘+简报落盘 | 反诘 1 次 + 2 个关键问题（选择题），口头确认即可 |
| 资源侦察 | 简报+URL 抽查+Spike | 1 次搜索 + 关键算法 Spike（Spike 证据必须落盘） |
| 方案自检 | 3 方案+文档 | 对话里 2 方案对比+推荐，等用户点头 |
| 并行执行 | 契约+双分支子代理 | 单文件项目直接主代理做；多文件才拆并行 |
| 独立审查 | 必过关卡 | 小项目可跳过（用户可豁免），但审查发现必须修 |
| 验收 | 8 条数字+命令 | 保留核心可测项（测试全绿+能玩+截图），文档从简 |

**核心保留项**（不可裁剪）：用户原话记录 / 验收可测化 / 证据落盘 / 完成前实测 / 已知限制诚实声明。
