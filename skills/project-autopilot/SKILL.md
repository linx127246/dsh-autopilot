# Project Autopilot（全自动项目交付流水线）

> 唯一目标：每个项目完全按流程执行，不依赖执行者自觉。所有硬规则机械可查：检查"文件是否存在、字段标题是否命中、ID 是否独立"，不检查"我有没有记住"。

## 0. 触发与分级

1. **触发**：任务含"做个/开发/搭建/实现/写一个/帮我写个/做一个系统/开发一个应用(网站/工具/游戏)"或多步骤交付物 → 启用本技能。单步问答/闲聊 → 不启用。**拿不准 → 按项目处理（宁可多流程，不可漏流程）。** **判定必须对话内显式声明**："本次判定：项目级/非项目级 + 理由"，用户可见可纠偏。
2. **分级**：四维打分（规模/影响面/复杂度/工期各 1-4 分）→ S(4-8)/M(9-14)/L(15+)。**打分锚定客观计数**（"复杂度 2 因为 X 个集成点"，无计数依据 = 分数无效）；**含 2+ 独立模块或 2+ 交付文件 → 至少 M 级**。定级写入检查点JSON并在对话内播报，**中途改级需用户确认**。分级只影响时间盒/预算/轮数，**不影响任何硬规则**——S 级同样要反诘、简报落盘、侦察、独立审查、并行判定。

## 1. 流水线总图

```
项目 → ①意图挖掘 → ②资源侦察 → ③方案自检 → ④并行执行 → ⑤验证迭代 → ⑥交付 → 复盘
         ↑____________________ 变更管理（任何阶段可触发）____________________↓
贯穿：自主原则六条 / 问题预算 / 冲突仲裁表 / 失败协议 / 检查点恢复
```

**铁律**：A. 只有 §2 关卡全部通过才可进入下一阶段；B. **文件不存在 = 没做过**，任何口头声称无效；C. 主代理自证"够好"一律无效；D. 检查结果必须落盘进检查点JSON 的 `gate_log`，不落盘 = 没检查；E. **随机内容抽查**：每次过关随机抽 1-2 个字段/URL，证据必须来自工具副作用（web_search 调用记录/测试输出文件/提问留痕），抽查点随机不可固定，抽查结果写 `gate_log`——文件存在 ≠ 内容真实，**禁止"手打"证据**。

## 2. 阶段关卡（机械检查，逐关放行）

检查方法固定：用 read/grep 打开文件验证，不凭记忆。**进入下一阶段前**：跑本关检查 → 输出追加 `gate_log` → 更新 `当前阶段` → 才可推进，缺一步即违规。

| 关卡 | 检查内容（机械） | 不满足 → |
|---|---|---|
| ①→② | `docs/superpowers/specs/01-任务简报.md` 存在；grep 命中 `## 反诘记录`、`## 资源侦察结论`、`## 验收标准` 三标题行 | 回①补做，禁带缺过关 |
| ②→③ | `docs/superpowers/specs/02-资源简报.md` 存在（S 级可一行结论，文件必须存在） | 回② |
| ③→④ | `docs/superpowers/specs/03-实施方案.md` 存在；grep 命中 `## WBS与依赖图`、`## 验收清单` | 回③ |
| ④→⑤ | 每个子代理交付物在 `artifacts/` 有证据文件（测试输出/截图）；依赖图独立分支数 ≥2 时检查点JSON `subagents` 必须 ≥2 个ID | 回④补证据 |
| ⑤→⑥ | `docs/superpowers/specs/04-交付报告.md` 存在；grep 命中 `## 独立审查记录`；审查子代理ID ≠ 主代理ID | 回⑤补独立审查 |
| 交付完成 | 六连清单 + 终态自检输出 + 用户确认 | 未确认 → 置"待验收"终态 |

**独立审查不可替代（硬性）**：完成度审查必须由独立子代理执行——新开、独立上下文的子代理，只收到"交付物+验收清单"，**看不到主代理自评**；审查记录必须写审查子代理ID、挑刺清单逐条对应验收清单、主代理逐条回应、修复证据。主代理自证、代写审查记录、引用主代理结论 = 没有审查，关卡不过。
**独立审查防污染三件套**：① 审查 prompt 用**固定对抗模板**（"你是刁钻用户，唯一任务是找茬；从功能/质量/体验/视觉/健壮五维各挑问题；找不到 3 个以上实质问题就是失职"）——主代理只填项目上下文，不可改写措辞；② 审查报告由**审查子代理直接落盘**到 `reviews/`，主代理只允许在其后追加"回应"段落；③ **禁止"重新派审查直到通过"**，全部审查报告保留，任一审查发现实质问题未回应 = 不得交付。

## 3. 六阶段硬规则

### ① 意图挖掘（反诘式澄清）
1. **反诘 ≥1 次（强制）**：挑战一个假设测需求强度（"为什么一定要X""X真的必要吗"）。事实澄清（问形式/范围）≠ 反诘。记录须含"挑战的假设 + 用户原话/维持理由"；草案模式须标注"假设维持"。
2. 一次一问，选择题带默认推荐，2-3 轮封顶。失联/无应答 → **简报草案模式**（按最合理假设出草案+标注假设），绝不死锁。
3. 产出 `01-任务简报.md`（8 段式：背景/目标/用户/场景/边界/约束/验收标准/未决疑问），**强制三字段**：
   - `## 反诘记录`（≥1 条，见上）
   - `## 资源侦察结论`（查过哪些维度 + 用/不用现成轮子的结论 + 来源URL，≥1 句）
   - `## 验收标准`（全部可测化："快"→"3秒内"，禁形容词；**写入后任何阶段不许缩水**，改 = 变更管理）

### ② 资源侦察
1. **最低门槛**：至少过"现有方案"维度（web_search 查现成轮子/同类实现），S 级不例外。时间盒 S≤15min / M≤1h / L≤半天。
2. 一手优先 / 双语搜索 / 多源交叉，每条资源附来源URL（防幻觉引用）；**来源 URL 必须主代理随机抽查实际访问（强制动作），抽查结果写 `gate_log`，证据禁止"手打"**。
3. 高风险盲区（选型/安全/依赖）→ 阻断开工先补验；低风险 → 标注进简报带病进入。
4. 关键选型写最小 Spike 实测再定案。产出 `02-资源简报.md`（每资源一行：是什么/适配度/风险/采用|备用|否决+理由）。

### ③ 方案自检
1. 2-3 个真实差异方案（稳妥/激进/极简）+ 明确推荐（推荐非折中，按简报约束计算）。
2. 自检五连问：占位符扫盲 / 与简报一致性 / 可行性（选型有 Spike 证据）/ 验收可测性 / 范围（一个执行周期装得下，装不下拆子项目）。
3. L 级派红队子代理挑刺，主代理逐条回应（采纳/反驳）后定稿。
4. 产出 `03-实施方案.md`：决策记录/选型证据/**WBS+依赖图（ASCII）**/里程碑/风险登记册/**验收清单**（与简报验收标准逐条对应）。

### ④ 并行执行
1. **拆解判定（与分级无关）**：开工先画依赖图。**存在 ≥2 个互不依赖的独立分支 → 必须拆子代理并行，S 级同样适用**；依赖图分支数写入检查点JSON `并行分支数`，实际子代理ID写入 `subagents`，二者不符 = 违规。依赖图必须覆盖 WBS 全部任务，**不许为不拆而把独立任务串成链**。
2. 契约先行：公共接口（数据结构/函数签名/组件props）先钉死；任务包自包含（背景/契约/验收/交付位置/验证要求——子代理看不到主对话）。
3. 并行度 ≤2（429 限流），指数退避 5s/15s/45s×3，错峰启动；主代理唯一集成点+最终仲裁。
4. 子代理必须贴测试证据，主代理抽查；UI 部分截图核对；耗时长的环节（下载/多源调研/分析）优先拆子代理，主代理不阻塞等待。

### ⑤ 验证迭代
1. **证据先于断言**：每条"完成"必须挂证据文件（测试输出/截图/试用记录），空口不算。
2. 验证金字塔：测试全绿 → 真机试用 → 截图+视觉核对 → 验收清单逐项打勾。
3. 完成度五维审查（功能/质量/体验/视觉/健壮）：**由独立子代理执行**（见关卡⑤→⑥），主代理提供材料+逐条回应挑刺。
4. 迭代预算 3 轮；**降级 = 问用户**（带默认推荐），禁止悄悄降级；降级项写进交付报告"已知限制"+附"为什么无解"的证据。
5. 确定性脚本校验+原始证据留档；bug 先定位根因再修（systematic-debugging），修完回归验证。

### ⑥ 交付
1. 六连清单：可运行 / 测试全绿 / 已知问题 / 使用文档 / 截图证据 / 验收结果逐项。
2. **`## 独立审查记录` 强制字段**：审查子代理ID / 挑刺清单（逐条对应验收清单）/ 主代理逐条回应 / 修复证据。没有这一节 = 交付未完成。**已知限制区禁止掩埋属验收清单的未完成项**——验收项必须先修或先降级问用户，否则不许进限制区。
3. **终态自检**：重跑 §2 全部关卡检查命令，输出原样贴在交付报告末尾。
4. 合规复核（许可证/API 条款/隐私）。五段汇报（做了什么/证据路径/怎么用/已知限制/下一步）。
5. **签字门**：交付报告 = 验收申请，用户确认才算完成；不回复 → 置"待验收"终态（有终态不悬挂）。
6. 归档：01-04 四份文件同处 `docs/superpowers/specs/`，全程可追溯。

## 4. 贯穿机制

### 自主原则（六条）
1. 永不停下问"下一步怎么办"，自己决策推进。2. 需权限 → 自动申请（唯一合法打断）。3. 路不通 → 止损换路，**换路不得降低验收标准**。4. 每阶段播报一两句不刷屏。5. 只有用户能做的 → 攒批一次问清，其余并行继续。6. 方向性难题（多轮迭代无解）→ 停下来问一次。

### 问题预算
每项目最多问 N 次（S=2 / M=3 / L=5），每个问题必带默认推荐+超时继续（2 分钟不回复按推荐执行）。

### 冲突仲裁优先级表
1 用户实时指令 > 2 安全/合规/不可逆红线（删数据/花钱/对外发消息/隐私） > 3 本技能铁律（关卡/证据/降级需确认/验收不缩水/定级不改） > 4 自主原则（默认全自动，受问题预算约束） > 5 时间盒与效率（最末，可被上面任意级覆盖）

### 需求变更管理
任何阶段发现需求有变：受理 → 影响评估（动了哪些已锁定工件）→ 工件更新（标注版本）→ 受影响阶段重跑 → 记入变更登记册。

### 失败协议（三终态）
每个项目必须有终态：交付 ✅ / 终止 ❌ / 暂停存档 ⏸️，不允许无主悬挂。终止触发器：子代理全挂且重试仍失败 / Spike 证明不可行 / 侦察证明无解或成本失控 / 用户失联且问题属方向级。终止收尾：《终止报告》（尝试了什么/卡在哪/证据/替代路线）→ 存档 → 报告用户（失联则直接归档）。

### 检查点恢复
所有进度落盘 `workspace/state/<task>.json`，字段：`分级 / 当前阶段 / gate_log[] / 并行分支数 / subagents[] / 问题预算已用 / 终态`。用户喊停 = 存档暂停；说继续 = 无损恢复续接（优先续接而非重跑）。

## 5. 收尾：复盘

交付或终止后复盘：哪个环节拖后腿 / 踩了什么新坑 / 什么环节失效 / 下次怎么避免。成功失败都复盘，经验写回附录C 或 AGENTS.md。
