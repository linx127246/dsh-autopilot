# Project Autopilot（全自动项目交付流水线）

## 核心原则

接到项目任务后，**全自动**跑完六阶段：意图挖掘 → 资源侦察 → 方案自检 → 并行执行 → 验证迭代 → 交付。除权限/账号等必要操作外，**绝不要求用户主动操作或提醒**；遇到困难主动克服，必要时自动申请权限。

## 触发判定（先分类再行动）

任务属于"项目级"（多步骤、有交付物、需端到端）→ 启用本技能。
任务属单步问答/闲聊/一次性小事 → 不启用，正常处理。

## 流水线总图

```
项目任务 → 【分级】→ ①意图挖掘 → ②资源侦察 → ③方案自检 → ④并行执行 → ⑤验证迭代 → ⑥交付 → 【复盘】
                                        ↑__________变更管理通道（任何阶段可触发）__________↓
贯穿：自主原则 / 问题预算 / 冲突仲裁表 / 失败协议 / 检查点恢复
```

## 阶段 0：项目分级（定级后写进简报，中途不许改级，改级需用户确认）

四维打分（权重固定）：交付物规模（文件/代码量，1-4分）、影响面（用户/系统数，1-4分）、复杂度（技术难度/集成数，1-4分）、预计工期（1-4分）。总分 4-8=S / 9-14=M / 15+=L。S/M/L 决定：侦察时间盒、是否派红队、迭代轮数预算、问题预算、子代理数量。

## 阶段 1：意图挖掘（反诘式澄清）

- 心法：不问"想要什么"，问"解决什么"；问过去的行为（Mom Test），不问未来假设
- 三层六问：目标（解决什么问题/现状/痛点）→ 场景（谁用/什么场景/失败案例/边界）→ 约束（时间/预算/平台/维护者/验收）
- 技法：反诘质询（始终尖锐，对方案不对人——每个假设直接反驳验证，测需求强度）/ 具象化测试（描述成品的一天）/ 形容词→验收指标（"快"→"3秒内"）
- 纪律：**一次一问**、给选择题带默认推荐；2-3 轮封顶
- 用户失联/不回复/提问被中止 → **简报草案模式**：按最合理假设出草案并标注假设，进入阶段 2（侦察不需要用户），用户回来再确认。**绝不因等不到回答而死锁**。注：真实场景下用户在线时应先按"一次一问"正常提问，确认用户确实无应答/超时才切换草案模式（测试情境预先声明失联则可直接草案）
- 产出：8 段式《任务简报》存档于 `docs/superpowers/specs/`（背景/目标/用户/场景/边界/约束/验收标准/未决疑问），验收标准必须可测化

## 阶段 2：资源侦察（六维度双语信源）

- ① 现有方案：web_search + Google/Bing + GitHub + HN + 知乎/V2EX/少数派
- ② 开源库：GitHub API（星/活跃/许可）+ npm/PyPI 注册表 + awesome 清单
- ③ 技能：`npx skills find`（先设 `$env:npm_config_cache`，见操作层）
- ④ 文档/API：官方文档一手优先 + StackOverflow
- ⑤ 设计资产：Unsplash/Pexels/Fonts/Iconify + Figma 模板（UI 类项目）
- ⑥ 用户之声：B站搜索（免登录；"XX 测评/横评/避雷"，读标题/简介/评论）+ 小红书/抖音（用户已登录的浏览器）
- 纪律：一手优先 / 双语搜索 / **多源交叉** / 每条资源附来源 URL（防幻觉引用，主代理抽查可验证）
- 时间盒：S≤15min / M≤1h / L≤半天，到点收网
- 盲区分级：高风险盲区（选型/安全/依赖）→ 阻断开工，先补验；低风险盲区 → 标注进简报，带病进入
- 合规前移：许可证商用条款、API ToS 选型时当场查
- 社区情报 = 假设，需多平台交叉 + 与用户确认后才进简报
- 关键选型：自动写最小 Spike 验证代码实测再定案
- 产出：《资源简报》——每资源一行（是什么/适配度/风险/采用|备用|否决 + 理由），分决策区/Spike区/盲区

## 阶段 3：方案自检

- 2-3 个真实差异方案（稳妥/激进/极简）+ 明确推荐（推荐非折中，按简报约束计算）
- 选型挂 Spike 证据；偏离简报必须显式标注"偏离+理由"
- 自检五连问：①占位符扫盲 ②与简报一致性 ③可行性（每个选型有 Spike 证据？）④验收可测性 ⑤范围（一个执行周期装得下？装不下就拆子项目）
- L 级：派子代理红队挑刺（证明方案不行），主代理逐条回应（采纳/反驳）后才定稿
- 分歧处理：只问花钱💸和不可逆⚠️动作（带推荐选择题）；技术方向全自动
- 产出：《实施方案》（决策记录/选型证据/WBS任务分解+依赖图/里程碑/风险登记册/验收清单）+ 存档

## 阶段 4：并行执行

- 依赖图先行：无依赖并行 / 有依赖分阶段 + 阶段关卡（阶段产物先验证再放行）
- 契约先行：公共接口（数据结构/函数签名/组件props）先钉死，谁也不许私自改
- 任务包自包含：背景/契约/验收标准/交付位置/验证要求（子代理看不到主对话）
- 并行度 ≤2（免费模型 429 限流），错峰启动，指数退避（5s/15s/45s×3）
- 子代理沟通：共享工作区（`artifacts/` + `reviews/` 目录约定）+ 互相评审；子代理间无直接消息通道（运行时限制），主代理转发；主代理唯一集成点+最终仲裁
- 验证不信任：子代理必须贴测试证据；主代理抽查；UI 部分截图
- 操作细节：项目根 `.npmrc` 固定 `cache=工作区\.npm-cache`；跑服务用后台 job + 健康检查 + job_kill 记账；输出重定向避免管道 EPERM；资源占用纪律——临时文件用完即清，不堆磁盘

## 阶段 5：验证迭代

- 宪法：**证据先于断言**——每条"完成"宣称必须挂证据（测试输出/截图/试用记录），空口不算
- 验证金字塔：测试全绿 → 用户视角真机试用 → 截图+视觉核对 → 验收清单逐项打勾
- 完成度五维审查：功能（验收清单可演示）/ 质量（无已知bug或显式降级）/ 体验（用户视角操作）/ 视觉（截图核对居中/对齐/配色/响应式）/ 健壮（边界/连点/缩放/断网/异常）
- 审查主体分离：主代理操作，**独立子代理扮演刁钻用户挑刺**（连点/点边缘/窗口缩放/非法输入/断网），主代理逐条回应
- 刁钻用户操作协议：网页 → 串行排期独立 tab；Electron → CDP；原生 Win32 → 回退 CLI/API 冒烟 + 静态审查
- 迭代轮数预算：3 轮，超预算走降级通道
- 降级 = 问你：多轮无解必须问用户（带默认推荐），**禁止悄悄降级**；降级项必须显式写进交付报告"已知限制"区 + 附"为什么无解"的证据
- 确定性脚本校验（命令跑出来的硬证据）+ 原始产物留档（测试输出/截图原件不许删）
- bug 纪律：先定位根因再修（systematic-debugging），修完回归验证
- 退出条件：验收清单全勾；对照钢琴块反面案例清单（见下）

## 阶段 6：交付

- 六连清单：可运行 / 测试全绿 / 已知问题（如实列）/ 使用文档 / 截图证据 / 验收结果逐项
- 合规复核：许可证商用/API 条款/隐私
- 五段汇报（对话内完整汇报 + 存档）：做了什么（对应简报目标）/ 证据（路径链接）/ 怎么用 / 已知限制 / 下一步建议
- **签字门**：交付报告 = 验收申请，用户确认后才算交付完成；用户不回复 → 项目置"待验收"态（有终态，不悬挂）
- 归档：简报 + 方案 + 交付报告同处，全程可追溯

## 收尾：复盘（流水线自我进化）

交付或终止后复盘：哪个环节拖后腿 / 踩了什么新坑 / 什么环节失效 / 下次怎么避免。**成功失败都复盘**，经验写回本技能"经验库"章节或 AGENTS.md。

## 贯穿机制

### 自主原则（六条）

1. 永不停下问"下一步怎么办"——自己决策、自己推进
2. 需要权限 → 自动发起权限申请（唯一合法的"打断"）
3. 一条路不通 → 止损，重新侦察换路，绝不硬磨；**换路不得降低验收标准**
4. 进度播报：每阶段一两句，不刷屏
5. 只有用户能做的（账号/付费/人工审批）→ 攒批一次性问清，其余工作并行继续
6. 方向性难题（多轮迭代无解）→ 停下来问用户一次

### 问题预算（防"问用户"被滥用）

每项目最多问 N 次（S=2 / M=3 / L=5），问完即止。每个问题必带默认推荐 + 超时继续（2 分钟不回复按推荐执行）。

### 冲突仲裁优先级表

```
1 用户实时指令（最高）
2 安全/合规/不可逆红线（删数据/花钱/对外发消息/隐私）
3 技能铁律（证据先于断言/降级需确认/验收标准不缩水/定级不改）
4 自主原则（默认全自动，受问题预算约束）
5 时间盒与效率规则（最末，可被上面任何一级覆盖）
```

### 需求变更管理

任何阶段发现需求有变（用户新要求/侦察推翻事实/执行中认知更新）：变更受理 → 影响评估（动了哪些已锁定工件）→ 工件更新（标注版本）→ 受影响阶段重跑 → 记入变更登记册。

### 失败协议（三终态）

每个项目必须有终态：交付 ✅ / 终止 ❌ / 暂停存档 ⏸️，不允许无主悬挂。
终止触发器：子代理全挂且重试仍失败 / Spike 证明方案不可行 / 侦察证明无解或成本失控 / 用户失联且问题属方向级。
终止收尾：《终止报告》（尝试了什么/卡在哪/证据/替代路线）→ 存档 → 报告用户（失联则直接归档）。

### 检查点恢复

简报/方案/进度记录全部落盘（`workspace/state/<task>.json`）。用户喊停 = 存档暂停；说继续就无损恢复（优先续接而非重跑）。

## 反面案例对照清单（钢琴块教训）

完成度审查前逐项自查：
- 点击无效 → 真机试用连点/点边缘测试
- 游戏不居中 → 截图 + 视觉核对布局
- bug 多 → 系统化边界测试（非法输入/空值/异常路径）
- 完成度不够 → 五维审查清单逐项打勾，禁止凭感觉说"完成"

## 红灯表（防偷懒自检——出现即 STOP）

- "时间盒到了所以带盲区交付" → 高风险盲区必须先补验
- "这个算降级项" → 降级必须问用户 + 写进交付报告，禁止悄悄降级
- "验收标准可以放宽一点" → 验收标准永不缩水
- "这个问题问一下用户就行" → 查问题预算，先给默认推荐
- "我检查过了没问题" → 证据呢？贴出来
- "换个方案做吧" → 换路可以，验收清单一条不许少
- "项目先放着" → 必须落终态：交付/终止/暂停存档
